# 아이담(Aidam) — 정통 성명학 기반 아기 작명 사이트 설계서

- 작성일: 2026-11-03
- 상태: 사용자 검토 대기
- 서비스명: **아이담** (영문 **Aidam**) — "아이의 이름에 의미를 담다"

## 1. 목적과 성공 기준

### 1.1 목적
새로 태어날(또는 태어난) 아기의 이름을 **정통 성명학의 작명 4대 요소**에 근거해 추천하고,
부모가 직접 지은 이름(셀프작명)도 같은 기준으로 분석해 주는 웹사이트를 만든다.

### 1.2 작명 4대 요소 (점수의 뼈대)
1. **사주·용희신 분석** — 만세력으로 사주팔자를 세우고, 가장 이롭고 부족한 기운인 용신(用神)·희신(喜神)을 파악한다.
2. **음령오행(소리오행)** — 한글 이름 첫소리(초성) 오행이 성→이름 순으로 상생하는지, 부를 때 어감이 부드러운지 본다.
3. **자원오행(한자 오행)** — 한자 자체의 오행이 사주에 부족한 오행(용희신)을 실제로 채워주는지 본다.
4. **수리성명학(획수 길흉)** — 원형이정 4격(초년·청년·장년·말년/총운)이 81수리 길수로 구성되는지 본다.

보조 요소: 소리(발음)음양, 수리음양, 수리오행, 다둥이(형제자매) 궁합.

### 1.3 성공 기준
- 같은 입력이면 언제 어디서 실행해도 **항상 같은 결과**가 나온다(재현성).
- 출생 정보가 기기 밖으로 **전송되지 않는다**(안전성·개인정보).
- 추천 한자는 모두 **대법원 인명용 한자** 목록 안에 있다.
- 모든 점수에는 **근거 문장**이 붙는다(왜 길한지/흉한지).
- 학설이 갈리는 항목은 **선택할 수 있고, 다른 학설 결과도 함께** 보여준다.
- 모바일 한 손 조작으로 3단계 안에 추천 결과까지 도달한다.

### 1.4 하지 않는 것 (v1 범위 밖)
- 회원가입·로그인·서버 저장 (찜 목록은 기기 내 저장)
- 유료 결제, 상담 연결
- 대운·세운 등 작명과 무관한 운세 풀이
- 제왕절개 택일
- AI 생성형 문장 (모든 해설은 규칙 기반 템플릿)

## 3. 참고한 기존 서비스와 차별점

| 서비스 | 특징 | 아이담에서 취할 점/차별점 |
|---|---|---|
| 모두맘 | 성씨·생년월일·출생지역 입력 → 획수·자원오행으로 한자 자동 추천, 조건 충족 시 '추천' 표시 | 조건 충족 배지 방식 채택 |
| 명인 AI 작명 | 용신 중심 추천, 기존 이름 점수 평가 | 셀프 분석 점수화 채택 + 근거 문장 강화 |
| 넴유베 | 셀프작명 도우미(인명용 한자 → 81수리·수리오행 검토) | 음절별 한자 고르기 UI 채택 |
| 작명가(협회공인) | 훈민정음(해례본) 한글오행 강조 | 학설 선택 + 병기로 해결 |

차별점:
1. **학설 병기** — 발음오행(해례본/운해본), 자시 처리, 여성 강수, 불용한자 등 학설을 바꿔가며 결과 비교.
2. **출생 시간 모름 대응** — 12시진 모두 계산해 공통 용신과 신뢰도(예: 12개 중 9개 水) 제시.
3. **같은 음, 더 좋은 한자 제안** — 셀프 분석에서 같은 소리의 대체 한자로 점수가 오르는 조합 제안.
4. **다둥이 세트 추천** — 쌍둥이·형제자매 이름을 묶음 단위로 궁합 점수화.
5. **완전 오프라인·무전송** — PWA 설치 후 인터넷 없이 동작.

## 4. 시스템 구조

```

├─ packages/engine/          # 순수 TS 성명학 엔진 (DOM 의존 없음)

│  ├─ src/score/             # 100점 채점과 근거 문장
│  ├─ src/recommend/         # 후보 생성·탐색·정렬
│  ├─ src/siblings/          # 다둥이 궁합·세트 추천

│  ├─ src/pages/             # 홈, 작명, 결과, 리포트, 셀프분석, 다둥이, 만세력, 찜, 안내
│  ├─ src/components/        # 디자인 시스템 컴포넌트
```

- 패키지 관리: pnpm 워크스페이스, lockfile 커밋, 의존성 버전 고정.
- 엔진 공개 API(요지):
  - `computeSaju(birth: BirthInput, opts: SajuOptions): SajuResult`
  - `analyzeName(input: NameInput, saju: SajuResult | null, opts: SchoolOptions): NameReport`
  - `recommendNames(profile: Profile, prefs: Preferences, opts: SchoolOptions): Recommendation[]`

### 5.2 빌드 산출물 (`packages/engine/src/data/*.json`)
- `hanja.json`: `{ ch, readings[], meaning, strokes(원획), totalStrokes, radical, element, elementBasis, elementConfidence, nameUse, edu, negative, bulyong }[]`
- `surnames.json`: 한국 주요 성씨 약 120개 + 복성(남궁·황보·제갈·사공·선우·서문·독고·동방). `{ hangul, hanja, strokes[], readings }` — 원획은 수작업 검증표와 대조.
- `syllables.json`: 이름용 음절 풀(첫 자/끝 자 위치별 남·여 가중치, 인기도).
- `suri81.json`: 81수리 표(격 이름, 길흉 3단계, 해설).
- `blocklists.json`: 부정 뜻 키워드, 전통 불용한자, 놀림 위험 단어.
- 모든 산출물은 SHA-256 해시를 `DATA_VERSION`으로 묶어 결과에 표기한다.

### 5.3 원획(성명학 획수) 계산 규칙
1. 부수가 변형된 글자는 **부수 원형 획수 + 잔획**: 氵→水 4, 扌→手 4, 忄→心 4, 犭→犬 4, 王(구슬옥변)→玉 5, 礻→示 5, 衤→衣 6, 罒→网 6, 耂→老 6, 月(육달월)→肉 6, 艹→艸 6, 辶→辵 7, 阝(우)→邑 7, 阝(좌)→阜 8.
2. 계산식: `원획 = max(총획, 강희부수획 + 잔획)`. 단 잔획 0(부수 자체인 글자, 예: 王=4)은 총획을 쓴다.
3. 부수 값이 둘 이상인 글자(예: 萬 `114.8 140.9`)는 강희자전 분류에 해당하는 변형부수 값을 우선한다 → 萬 = 15.
4. 숫자 한자는 뜻 획수: 一1 二2 三3 四4 五5 六6 七7 八8 九9 十10.
5. 검증표(골든 테스트): 河9 洙10 炫9 瑞14 珉10 道16 英11 陳16 鄭19 萬15 王4 琴13 表9 育10 李7 金8 朴6 崔11 等.

### 5.4 자원오행 산정 규칙 (신뢰도 3단계)
- **A(명확)**: 부수가 오행을 직접 나타냄
  - 木: 木 艸(艹) 竹 禾 / 火: 火(灬) 日 / 土: 土 山 田 阜(阝) / 金: 金 玉(王) 石 / 水: 水(氵) 冫 雨
- **B(통설)**: 성명학 사전에서 널리 쓰는 부수 배당
  - 木: 糸 衣 米 / 火: 心(忄) 人(亻) 馬 鳥 光 / 土: 女 里 邑 黃 / 金: 刀(刂) 戈 斤 貝 白 言 / 水: 子 魚
- **C(추정)**: 위에 없으면 훈(뜻) 키워드로 판정(물·바다·강→水, 나무·풀·꽃→木, 불·빛·해·밝을→火, 흙·땅·산·돌→土, 쇠·금·옥·구슬·보배→金). 그래도 없으면 획수 끝자리 오행으로 추정.
- 자주 쓰는 이름 한자(약 200자)는 수작업 검토표로 덮어쓴다.
- 리포트에 "근거: 부수 氵(물 수) / 신뢰도 A"처럼 표시하고, C 등급은 점수 가중치를 절반으로 낮춘다.
- 사전마다 자원오행이 다를 수 있음을 리포트에 명시한다.

## 6. 만세력 (calendar)

### 6.1 입력
- 양력 또는 음력(평달/윤달), 연·월·일, 시·분 또는 "시간 모름"
- 출생지(시·도 목록, 경도 포함, 기본 서울) 또는 해외(경도 직접 입력)
- 지원 범위: 양력 1900-01-01 ~ 2100-12-31, 음력 입력 1900 ~ 2050(변환 데이터 한계)

### 6.2 시각 처리
1. 한국 벽시계 시각 → UTC: 내장 표준시 이력표 사용(1908~1911·1954~1961 UTC+8:30, 1948~1960·1987~1988 서머타임 등).
2. **진태양시 보정(옵션, 기본 켬)**: 출생지 경도 기준 지방평균태양시 = UTC + 경도/15시간. 서울(126.98°E) ≈ 표준시 −32분, 부산(129.08°E) ≈ −24분.
   - **균시차(옵션, 기본 끔)**: 켜면 계절별 태양 남중 차이(±16분)까지 반영한 진태양시를 쓴다.
   - 보정 전과 후의 시주(또는 일주)가 달라지면 **두 결과를 나란히 보여준다**.
   - 근거(2026-11 조사): 명리학계는 "출생지 진태양시 사용"과 "현지 표준시 사용"으로 의견이 갈린다. 오픈소스 만세력 라이브러리(manseryeok)는 경도 보정·균시차·과거 표준시 보정을 기본으로 켜고, 현장 관행은 "출생 시각 −30분"이 흔하다. 그래서 경도 보정은 기본으로 켜되 끌 수 있게 하고, 결과가 갈리면 둘 다 보여준다.
3. 연주·월주는 **절입 순간(UTC)과 출생 순간(UTC)**을 비교해 결정(보정과 무관).
4. 일주·시주는 보정된 지방시 기준.

### 6.3 사주팔자
- **연주**: 입춘(태양황경 315°) 기준. `(연도 − 4) mod 60`.
- **월주**: 12절(입춘315·경칩345·청명15·입하45·망종75·소서105·입추135·백로165·한로195·입동225·대설255·소한285°)로 월지 결정, 월간은 연간에서 오호둔(甲己→丙寅 …).
- **일주**: 율리우스일(JDN) 기준 `(JDN + 49) mod 60` (0=甲子). 검산: 2000-01-01 = 戊午.
- **시주**: 子시 23:00~01:00(보정시각), 시간은 일간에서 오서둔(甲己→甲子 …).
- **자시 처리(옵션)**: 기본 = 23시부터 다음 날 일주(정통 자시). 대안 = 야자시(23~24시는 당일 일주 + 다음 날 자시 천간).
- 절기 시각은 astronomy-engine `SearchSunLongitude`로 계산(오차 1분 내). 골든 테스트: 2024 입춘 2024-02-04 17:27 KST, 2025 입춘 2025-02-03 23:10 KST, 2026 입춘 2026-02-04 05:02 KST(±2분).

### 6.4 경계 경고 ("여러 경우의 수")
- 출생 시각이 시진 경계 ±30분, 또는 절입 시각 ±24시간 이내면 "경계 출생" 배지와 함께 **대안 사주**를 계산해 용신이 바뀌는지 표시한다.
- 시간 모름 → 12시진 전부 계산 → 용신 다수결 + 신뢰도. 동률이면 3주(연·월·일) 분석 결과를 우선한다.

## 7. 사주 분석 (saju)

### 7.1 오행 세력 점수
- 위치별 가중치(일간 제외, 합 100): 년간 10, 월간 10, 시간 10, 년지 10, **월지 30**, 일지 20, 시지 10.
- 지지는 지장간 비율(월률분야)로 오행을 나눈다:
  子(壬10 癸20) 丑(癸9 辛3 己18) 寅(戊7 丙7 甲16) 卯(甲10 乙20) 辰(乙9 癸3 戊18) 巳(戊7 庚7 丙16)
  午(丙10 己9 丁11) 未(丁9 乙3 己18) 申(戊7 壬7 庚16) 酉(庚10 辛20) 戌(辛9 丁3 戊18) 亥(戊7 甲7 壬16)
- 시간 모름이면 시주 가중치를 빼고 80점 만점으로 정규화.
- 화면에는 (a) 8글자 본기 기준 오행 개수와 (b) 가중 세력(%) 두 가지를 보여준다.

### 7.2 신강·신약
- 십신 그룹: 비겁(같은 오행), 인성(나를 생), 식상(내가 생), 재성(내가 극), 관성(나를 극).
- 지지율 `r = (비겁 + 인성) / 전체`.
- 판정: r < 0.25 극신약 · < 0.45 신약 · ≤ 0.55 중화 · ≤ 0.75 신강 · 그 이상 극신강.

### 7.3 용신·희신 (억부 중심 + 조후 보정)
- **신약**: 나를 누르는 세 그룹(식상·재성·관성) 중 가장 강한 것으로 판단
  - 관성 최강 → 용신 인성(살인상생), 희신 비겁
  - 식상 최강 → 용신 인성, 희신 비겁
  - 재성 최강 → 용신 비겁, 희신 인성
- **신강**: 나를 돕는 두 그룹 중 강한 쪽으로 판단
  - 비겁 우세 → 관성이 있으면 용신 관성·희신 재성, 관성이 매우 약하면(5% 미만) 용신 식상·희신 재성
  - 인성 우세 → 용신 재성, 희신 식상
- **중화**: 조후가 급하면 조후 오행을, 아니면 세력이 가장 약한 오행을 용신으로, 그 오행을 생하는 오행을 희신으로.
- **조후 보정**: 월지가 亥子丑(겨울)인데 火 세력 < 10%면 火, 巳午未(여름)인데 水 세력 < 10%면 水를 "조후 필요 오행"으로 표시. 억부 결과와 충돌하지 않으면 희신으로 올리고, 중화일 때는 용신으로 쓴다.
- 기신 = 용신을 극하는 오행, 구신 = 기신을 생하는 오행, 한신 = 나머지.
- **이름 오행 선호도**(자원오행 채점에 사용): 용신 +1.0, 희신 +0.8, 한신 +0.3(용신과 같은 편) 또는 −0.2(반대 편), 구신 −0.5, 기신 −1.0.
- 리포트에는 판단 과정을 문장으로 남긴다. 예: "월지 子水가 왕성하고 관성이 강해 신약 → 인성(水)을 용신으로…"
- **단순화 고지**: v1은 천간합·지지 삼합/방합의 오행 변화(합화)를 세력에 반영하지 않고, 합·충 관계는 참고 정보로만 표시한다.

## 8. 이름 분석 (name)

|---|---|---|---|---|
| 원격(元) | 초년운 | 이름1+이름2 | 이름1 | 이름 전체 |

### 8.2 81수리 길흉 (3단계)

### 8.3 수리오행 / 수리음양
- 수리오행: 각 격 끝자리 1·2 木, 3·4 火, 5·6 土, 7·8 金, 9·0 水 → 원→형→이 순으로 상생이면 가점.
- 수리음양: 글자별 원획 홀수 = 양, 짝수 = 음. 전부 같으면 불균형(흉), 섞이면 조화(길).

### 8.5 소리(발음)음양

- 성+이름에 양·음이 섞이면 조화(1.0), 한쪽+중성만이면 보통(0.6), 한쪽뿐이면 불균형(0).

### 8.6 어감·실용 검사
- 실제 발음 추정(연음·비음화·유음화 주요 규칙). 예: 석민 → [성민]. 발음이 크게 바뀌면 안내한다.
- 같은 음절 반복, 성과 이어 읽을 때 놀림 위험 단어(블록리스트) 차단.
- 부정적 뜻의 한자(훈에 죽을·병·근심·망할·슬플 등 포함)는 추천에서 제외하고, 셀프 분석에서는 경고.

## 10. 추천 알고리즘 (recommend)

1. **입력**: 성씨(한자·읽기), 성별, 사주 결과, 선호 조건(글자 수 1~2, 돌림자와 위치, 꼭 넣을 음/피할 음·초성, 스타일: 인기/균형/독특, 학설 옵션).
2. **음절 풀 구성**: 위치별 이름용 음절(첫 자·끝 자 각 약 80개, 성별 가중치). 돌림자가 있으면 그 위치를 고정한다.
3. **한글 이름 생성·1차 필터**: 음절 조합 → 블록리스트·반복·발음 규칙 → 음령오행·소리음양·어감 점수로 상위 1,500개를 남긴다.
4. **음절별 한자 후보**: 해당 음(두음 포함)의 인명용 한자 → 부정 뜻 제외(옵션 시 불용 제외) → (자원오행 선호도, 교육용·이름 빈도, 코드값) 순으로 상위 12개.
5. **획수 조합 탐색**: 성 획수로 4격이 모두 길(엄격 모드)인 (획1, 획2) 쌍을 미리 계산해 두고, 한글 이름마다 12×12 한자 조합 중 허용 쌍만 채점한다.
6. **정렬**: 총점 내림차순 → 한글 이름(유니코드 순 = 가나다순) → 한자 코드값. 한글 이름당 상위 2개 한자 조합만 남겨 다양성을 확보한다.
7. **출력**: 상위 100개, 20개씩 페이지. 난수를 쓰지 않으므로 "다시 추천"은 다음 페이지를 보여준다.
- 계산량은 최대 약 22만 조합으로, Worker에서 1초 이내를 목표로 한다.

- **다크 모드**: 토큰을 재정의해 지원한다(밤중 수유 시간 사용 고려).
- **글꼴**: 본문 Pretendard, 제목 고운돋움. 둘 다 자체 호스팅(외부 요청 없음).
- **사용성**: 모바일 우선(360px~), 콘텐츠 폭 최대 560px, 터치 영역 44px 이상, 하단 고정 주요 버튼, 단계 진행 표시, 입력값 자동 저장(이어하기), 한자 용어 옆 쉬운 풀이와 "?" 도움말.
- **접근성**: WCAG 2.1 AA 대비, 키보드 조작, 스크린리더 레이블, 움직임 줄이기 설정 존중.

## 13. 안전성

- **개인정보**: 모든 계산은 기기 안에서. 분석·광고 스크립트 없음. 기기 저장(localStorage)은 찜·마지막 입력만, "기기에서 지우기" 버튼 제공.
- **보안**: CSP(`default-src 'self'`), 외부 리소스 없음, 의존성 최소화와 버전 고정, `npm audit` 통과.
- **입력 검증**: 날짜 범위, 존재하지 않는 날짜(음력 윤달 포함), 시간 형식, 한글 음절만 허용, 이름 길이(대법원 기준 5자 이내).
- **결과 안전**: 인명용 한자만 추천, 부정 뜻·놀림 위험 차단, 면책 문구("전통 성명학 이론에 따른 참고 정보이며 과학적으로 검증된 예측이 아닙니다. 출생신고 전 대법원 인명용 한자를 확인하세요.").
- **견고성**: 엔진 오류는 Worker에서 잡아 친절한 안내로 표시(화면이 멈추지 않음), React Error Boundary.

## 14. 재현성

- 엔진은 순수 함수만 쓴다: `Date.now()`, `Math.random()`, 기기 시간대·로캘 의존 금지(정렬은 코드값 비교, 표준시 이력은 내장 표).
- `ENGINE_VERSION`(semver)과 `DATA_VERSION`(데이터 해시)을 모든 결과에 표기한다.
- 입력과 옵션은 URL에 직렬화한다(버전 포함). 링크를 열면 같은 결과가 재계산되고, 버전이 다르면 안내한다.
- **분석 코드**: `hash(입력 + 옵션 + 버전)`의 앞 8자리를 리포트에 표시해, 두 사람이 같은 결과인지 확인할 수 있게 한다.
- 골든 테스트가 출력 스냅샷을 고정하므로, 알고리즘이 바뀌면 버전을 올려야 테스트가 통과한다.

## 15. 테스트 전략

- **단위 테스트(Vitest)**: 원획(검증표), 81수리, 4격 조합, 발음오행(두 학설), 소리음양, 두음법칙, 발음 추정, 자원오행 규칙, 일진(JDN), 오호둔·오서둔, 표준시 이력.
- **골든 테스트**: 절입 시각(입춘 2024~2026 등), 대표 출생일의 사주팔자, 대표 이름 리포트 스냅샷.
- **속성 테스트(fast-check)**: 1900~2100 임의 일시에서 예외 없음, 같은 입력 두 번 → 결과 동일, 추천 한자는 모두 인명용 목록 안, 점수 0~100 범위.
- **E2E(Playwright)**: 작명 마법사 완주, 셀프 분석, 공유 링크 재현, 모바일 뷰포트.
- **품질 게이트**: `tsc --strict`, ESLint, 테스트 전부 통과, 빌드 크기 예산(초기 JS gzip 250KB 이하, 한자 데이터는 지연 로드).

## 16. 배포

- GitHub 비공개 저장소(`aidam`)에 push. GitHub Actions는 테스트·빌드 검사만 한다.
- 배포는 Netlify 무료 플랜: 저장소에 `netlify.toml`(빌드 명령·출력 폴더)을 넣어 두어, 사용자는 Netlify에서 "GitHub로 로그인 → 저장소 선택 → Deploy" 클릭만 하면 된다. main 브랜치에 push할 때마다 자동 재배포된다. 대안: Cloudflare Pages.
- HashRouter를 써서 정적 호스팅에서 새로고침해도 깨지지 않게 한다.
- PWA: 서비스워커로 오프라인 캐시, 홈 화면 설치.
- 이 세션에서는 GitHub 접근이 막혀 있어, 접근이 복구되기 전까지는 로컬 git에 커밋하고 미리보기를 claude.ai 아티팩트로 게시한다.

- **만세력**: 네 기둥을 크게, 그 아래 평가 줄(타고난 힘·다섯 기운의 균형·이름에 담을 기운·태어난 시각)을 눌러 자세히. 별도 페이지 링크 대신 펼쳐 보기.
- **이름 풀이**: 맨 위 도구 줄(돌아가기 아이콘 · 한자 바꿔 보기 · 저장 · 공유) → 이름(한글·한자 같은 크기)과 점수 → 총평 → 만세력 → 항목별 풀이.
- **쌍둥이**: 사주·성별이 같으면 추천 목록도 같으므로, '아이마다 따로'에서는 아이들이 차례를 바꿔 가며 남은 이름 중 자기 순위가 가장 높은 이름을 하나씩 가져가 이름이 겹치지 않게 했다. 사주가 같으면 안내 문구를 보여 준다.

### 2026-11-04 — 실제 쓰는 이름만, 쌍둥이 고르기·궁합, 배포 절약 (v1.7, 엔진 1.2.0)
- **이름 후보**: 음절을 기계적으로 조합하지 않고, 실제로 쓰는 이름 목록(많이 쓰는·인기·개성 있는) 안에서만 고른다. 낱말처럼 들리는 이름(하지·지하·이유·하수·유린·도서·이민·수준 등)과 성과 이름 첫 글자가 같은 이름(정정우)은 언제나 뺀다. '흔하지 않은'은 같은 목록에서 덜 흔한 이름을 앞에 둔다. 돌림자로 후보가 너무 적을 때만 아주 흔한 음절끼리의 조합을 더한다.
- **성씨**: 인구가 아주 적은 성 한자(强·剛·程 등)는 숨기고 '드물게 쓰는 한자 더 보기'로만 보여 준다.
- **쌍둥이(아이마다 따로)**: 사주가 같으면 목록도 같게 보여 주고, 아이마다 '고르기'로 하나씩 고른다(다른 아이가 고른 이름은 막음). 다 고르면 다둥이 궁합(첫소리·부르기·어울림·사주)을 보여 준다. 세트 추천에도 궁합을 붙였다.
- **풀이 글**: 오행·한자 뜻·좋은 말·아쉬운 말·용어에 색과 굵기. 총평에 작명가의 풀이 문단을 더했다. 안내 문구는 가운데 정렬.
- **랜딩**: '이름을 담기 위해', 세 단계 설명을 한 줄씩 자세히. 마법사의 모든 단계에 '다음' 버튼.
- **배포**: Netlify 무료 크레딧(배포 1번 15, 월 300)을 아끼려고, 커밋 메시지에 [deploy]가 있을 때만 배포한다.

### 2026-11-04 — S등급만 추천·네쌍둥이·GitHub Pages (v1.8)
- **추천은 S등급(90점 이상)만**. 하나도 없을 때만 A등급까지 보여 주고 안내한다. 등급 걸러 보기 칩은 없앴다. 세트도 모든 이름이 S인 세트를 먼저 보여 준다.
- **풀이 판정**: 점수 아래에 '아주 좋은 이름(S)·좋은 이름(A)·무난한 이름(B)·아쉬운 이름(C)·바꾸기를 권해요(D)'.
- **네쌍둥이**까지 고를 수 있다(세트 추천은 엔진이 4명까지 지원).
- **한자 고르기**: '한글만' 칸을 없애고(다시 누르면 선택 해제), 이름에 많이 쓰는 한자부터 보여 준다.
- **고르기 단계**(무엇을 할지·아기 수·성별)는 항목을 누르면 선택만 되고 '다음'으로 넘어간다.
- **만세력 문장**: 요약을 짧은 한 문장으로 맞추고(숫자는 펼친 설명으로), 짧은 요약은 줄을 고르게 나눈다. 숫자·핵심어는 굵게.
- **설명**: '작명 원리와 출처'에 AI를 쓰지 않는 규칙 계산임과 100점 채점 기준을, 리포트에 '다른 작명 서비스와 점수가 다른가요?'(원획·학설·용신 방법·시간 보정)를 넣었다.
- **배포**: GitHub Pages(공개 저장소, 무료). `.github/workflows/pages.yml`이 main에 올릴 때마다 테스트·빌드·배포한다. Netlify는 [deploy]가 있을 때만 배포하도록 남겨 두었다(사이트를 지우면 됨).

### 2026-11-05 — 이름 느낌별 목록·조건 완화·모바일 버튼 (v1.9, 엔진 1.3.0)
- **이름 느낌이 실제로 다른 이름을 낸다.** 많이 쓰는 이름 목록(많이 쓰는 순)을 앞 60개(요즘)와 나머지(오래 써 온)로 나누고, 개성 있는 이름 목록을 늘렸다.
  - 요즘 많이 쓰는: 인기 이름 + 앞 60개 → 오래 써 온 이름 → 개성 있는 이름
  - 무난한: 오래 써 온 친숙한 이름 → 나머지
  - 흔하지 않은: 개성 있는 이름 → 오래 써 온 이름 → 요즘 인기 이름
  - 고른 느낌의 이름만으로 S등급이 8개 이상이면 그 이름만 보여 준다. 모자라면 다른 느낌의 이름을 뒤에 붙이고 목록에 '다른 느낌의 이름' 구분선을 넣는다. 순서는 등급 → 느낌 → 점수, 점수는 느낌과 상관없이 같다.
- **조건 때문에 추천이 비지 않는다.** 실제 이름 → 흔한 음절 조합(가중치 합 5 이상) → 이름 음절 조합(3 이상) 순으로 한 단계씩 넓히고, 그래도 하나도 없을 때만 '아쉬운 이름 미리 빼기'를 풀어 가장 나은 이름을 보여 준다(안내 문구 표시).
- **결과 화면**: S등급이 없으면 다음 등급으로 내려가 5개 이상 보여 준다(D 제외). 정렬에 '추천순'(느낌 맞는 이름 먼저)을 더했다. 고치기 옵션으로 걸러도 그 항목이 좋은 이름 중 가장 나은 등급을 보여 준다.
- **모바일**: '다음' 버튼을 화면 맨 아래에 고정하지 않고 고르는 칸 바로 아래에 둔다.

### 2026-11-05 — 결과에서 고르기·미리 쓴 풀이 글 (v1.10, 엔진 1.4.0)
- **결과 화면에서 고른다.** 이름 느낌(요즘 많이 쓰는·무난한·흔하지 않은)을 결과에서 바로 바꾸고(다시 계산), 등급은 S등급 / A등급 이상 / B등급 이상 / 전체 중에서 고른다. 처음에는 30개 이상이 되는 가장 높은 등급까지 보여 준다. 한 번에 30개씩, 세트는 20개.

- **총평·사주 풀이**는 문장 조각을 이름마다 골라 잇는다(문장마다 2~3가지). 같은 이름이면 늘 같은 글, 이름이 다르면 다른 글. 뜻 / 사주·획수·소리 / 맺음말 세 문단. AI는 쓰지 않는다.
